# M01 — First working ASTAGS webapp

**Target:** v0.1.0 (proposed)  
**Status:** planned; no implementation or release yet  
**Basis:** README.md, AGENTS.md, docs/PROJECT.md §§6–12, and the private SharePoint research audit (2026-11-25).

## Goal

Deliver a locally runnable browser-based parser workbench, with a separately testable engine, that imports a small UTF-8 main-text/apparatus sample, applies a versioned Göttingen Genesis profile, shows source-linked interpretations and diagnostics, and exports structured JSON. The same engine must work without the web UI. This milestone operationalizes roadmap phases 0–2 and includes a narrowly scoped part of phase 3 and JSON interchange from phase 4; it does not complete either later phase.

## Scope and design

- One minimal Genesis profile; paste or load a small passage or multi-entry UTF-8 sample and associated main text. Record passage, source provenance, and absence of typography. No bundled restricted texts.
- Support explicit single-word and short continuous lemmas, multiple readings and variation units, simple addition/omission operators, known numeric witnesses, one reviewed qualification/nested notation, and one patristic citation pattern (e.g. Ios or Tht). Resolve uniquely supported explicit lemma spans, individual witnesses and the citation's bibliographic fields. Profile vocabulary and examples are subject to review.
- Keep immutable source, normalized comparison data, tokens, lossless syntax, semantic results and diagnostics distinct. Unknown constructs and incomplete evidence remain visible with resolved/ambiguous/unresolved/invalid states. No automatic group expansion or implicit lemma inference in M01.
- One browser workspace: source and main-text input, profile selection, parse action, source-linked interpretation, token/syntax inspection, diagnostic navigation, summary of coverage, and JSON export. No account or project management yet. Polytonic Greek and keyboard access are essential.
- Prefer TypeScript and evaluate Node.js for tooling/runtime in P01; decide grammar approach and browser versus local server execution using a small technical evaluation. Local-only processing is the proposed default. No external services, database, UI framework or parser library unless a documented requirement justifies it.

## Release checklist

- [ ] Fresh checkout can start the local app with documented, reproducible instructions; no external LLM or data upload is required.
- [ ] User can load/paste main text and apparatus, select the profile, parse, inspect and export without coding.
- [ ] Engine can run independently of the UI and maintains generic mechanisms separate from edition-specific data.
- [ ] Original source is retained and all valid fixture text is covered; unknown/ambiguous/invalid information is visible, never discarded or invented.
- [ ] Supported cases meet agreed reviewed expectations; held-out results report denominators, errors and unresolved cases separately. No arbitrary aggregate accuracy threshold before the baseline. Repeated runs are deterministic.
- [ ] Semantic checks and JSON export are verified; the historical XML schema is not treated as validated.
- [ ] Scholarly review, rights for any included fixtures/reference data, and release license status are recorded. No protected data or unlicensed code is distributed. Public release is conditional on rights/license clearance.

## Explicitly deferred

Full Genesis/Isaiah coverage, formatted document adapters, witness-group/prime-group/exclusion expansion, Kopfleiste-derived implicit attestation, implicit lemma inference, complex nested readings and transpositions, persistent corrections and history, profile editor, schema repair and validated XML export, multiuser/project management, database, authentication, cloud deployment, AI assistance, search/comparison, morphology and witness reconstruction.

## Open decisions and blockers

- Stack, grammar formalism, precise input format and span/ID contracts are P01 decisions, not pre-approved choices.
- The minimal profile and fixture expectations require scholarly verification, including against the Genesis introduction; the audit's candidate cases and historical output are not authoritative. Missing review blocks a scholarly release, not synthetic-only development.
- Data rights and successor licensing are unresolved. Use synthetic or explicitly authorized material; keep private research inputs outside the distributed repository.
- The research audit reports that the supplied historical XSD does not compile. Repair/verification is a separate effort, not a dependency of JSON-only M01.
- The version, Genesis-first scope, local workbench, and JSON-only export are proposed planning choices. No dates or effort estimates are committed.
